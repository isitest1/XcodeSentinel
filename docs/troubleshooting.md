# トラブルシューティング

## 検出できない（状態が常に `unknown`）

1. **AX Inspector でツリーをダンプ**する（Debug → AX Inspector → 対象ウィンドウ選択）。
2. Claude パネルの要素が見えているか確認する。
   - 見えていない → パネルが独立ウィンドウの可能性。対象の再登録を試す。
   - 見えているがテキストが古い文言 → `Patterns.json` を更新する（設定画面 → Detection Patterns）。
3. `unknown` が 3 回連続すると監視は自動的に一時停止し、通知が出ます（CLAUDE.md 第 6.4 章）。
   原因を直してから再開してください。
4. 直らない場合は、ダンプした JSON を添えて Issue を作成してください
   （実在のプロジェクト名・パスが含まれないことを確認）。

## アクセシビリティ権限が外れた

- アプリの再署名や OS アップデートで権限が失われることがあります。
- アプリが検出して通知します。設定画面の導線から「システム設定 → プライバシーとセキュリティ →
  アクセシビリティ」を開き、XcodeSentinel を再度許可してください。

## Xcode を更新したら検出が壊れた

- Xcode 内 Claude パネルの AX 構造は非公開仕様で、更新で変わり得ます（織り込み済み）。
- 手順は「検出できない」と同じです。多くは `Patterns.json` の更新で対応できます。
- 構造自体が変わった場合は、AX Inspector のダンプを添えて Issue を作成してください。

## 自動再開されない

想定どおりの動作である場合があります。次の状態では**意図的に自動再開しません**（通知のみ）。

| 状態 | 理由 |
|---|---|
| `awaitingApproval` | 権限・ツール実行の承認はユーザーの判断が必要 |
| `awaitingUserAnswer` | Claude の質問に「continue」と返すのは有害な場合がある |
| `unknown` | 判別できないときに送信するのが最悪の挙動 |
| `errored` | 異常終了。原因確認が必要 |

そのほか次の安全上限に達している可能性があります（対象ごとの設定）。

- 1 日あたりの自動再開回数の上限（既定 12 回）
- 直前の再開からのクールダウン（既定 120 秒）
- 同一の停止に対するリトライ上限（1 回、同理由の再発でもう 1 回、3 回目で停止）
- Dry-run モードが有効（検出のみ行い送信しない）
- Quiet Hours の時間帯（通知のみ）

## 週次制限が解除されない

- 週次上限は 5 時間待ってもリセットされません。`weeklyLimited` を検出すると、
  短間隔のリトライはやめて長い待機（既定 30 分間隔で再確認）に切り替え、通知します。

## 外出先へ通知が届かない

- 設定画面の Webhook 設定でエンドポイント URL とテンプレートを確認してください。
- プリセット（ntfy / Pushover / Discord / Slack）を使うと設定が簡単です。
- 送信内容には対象の表示名・状態・時刻のみが含まれます。チャット本文やコードは送信しません。
